# 权限说明

## 0. 统一入口：设置 → 权限

Kaiming 需要的系统权限**只在一个地方**展示、检测和申请：**菜单栏面板 → 齿轮 → 设置 → 权限**。

权限页对所有权限给出同一套信息与操作：

| 内容 | 说明 |
|---|---|
| 状态 | 检测中 / 已授权 / 未授权（屏幕录制以真实 ScreenCaptureKit 能力为准） |
| 用途与后果 | 这项权限做什么、未授权时什么功能不可用 |
| 检测 | 重新读取当前构建的真实权限状态 |
| 请求权限 | 调用系统授权流程（系统可能只弹一次） |
| 打开系统设置 | 跳到「系统设置 › 隐私与安全性」对应页面 |
| 重置授权记录… | 仅屏幕录制：清除旧构建绑定到 TCC 的记录后重新授权 |
| 重启应用 | TCC 授权通常只对新进程生效，授权后重启一次 |

除该页外，任何界面都不再显示权限横幅或「请求权限」按钮：

- 菜单栏面板顶部不再有橙色权限横幅；
- 截图因权限失败时的恢复框只提供「打开权限设置 / 重启 Kaiming / 取消」；
- 长截图 HUD、截图服务错误只提示去「设置 → 权限」，不在截图流程里弹系统授权框。

实现入口：`Shared/PermissionCenter.swift`（应用层唯一权限状态与申请入口），底层仍使用
`ScreenCapturePermission` / `AccessibilityPermission` 两个 TCC 包装。

## 1. 屏幕录制（Screen Recording）

截图使用 ScreenCaptureKit（macOS 14+），它受 macOS TCC 的「屏幕录制」权限控制。

### 用途与影响

- 区域 / 窗口 / 全屏截图、长截图逐帧采集都需要它。
- 未授权时 `SCShareableContent` 返回**空列表**且不抛错，用户会看到「点了没反应」。

### 授权步骤

1. 菜单栏面板 → 齿轮 → **设置 → 权限**。
2. 在「屏幕录制」行点「检测」确认当前状态；点「请求权限」触发系统授权流程。
3. 若系统没有弹窗，点「打开系统设置」，在 **系统设置 → 隐私与安全性 → 屏幕录制** 中勾选 **Kaiming**。
4. **重启 Kaiming**（或权限页的「重启应用」）。TCC 的授权对已运行进程不会立即刷新。

### 为什么必须显式检查

ScreenCaptureKit 在未授权时：

- `SCShareableContent.excludingDesktopWindows(...)` 返回 **空列表**；
- 不抛错、不弹系统提示。

如果不处理空列表，用户会看到"点了没反应"。Kaiming 的处理：

- 权限页的「检测」调用 `ScreenCapturePermission.verifyAccess()` 做真实能力探测；
- `SCShareableContent` 的 `displays.isEmpty` 同样视为权限缺失；
- 截图实际失败时给出恢复框（打开权限设置 / 重启），日志记录（`Log.screenshot`）。

### 系统设置显示已授权，但截图仍提示未授权

这是 macOS TCC 的典型状态：屏幕录制授权与应用的**代码签名/CDHash** 绑定。重新构建（尤其 ad-hoc 签名）
后，系统设置里可能仍显示 Kaiming 已勾选，但当前二进制不再匹配旧授权记录，
`CGPreflightScreenCaptureAccess()` 会返回 false，甚至 ScreenCaptureKit 实际采集也失败。

Kaiming 1.1.1 起的处理：

1. **不再用 preflight 直接拦截**：每次截图都先尝试真实 ScreenCaptureKit 采集，能采集就直接成功；
   只有实际失败才提示授权。
2. 权限状态用真实 SCK 能力探测，不再只信 preflight（设置 → 权限 → 屏幕录制「检测」）。
3. 实际失败时弹出恢复框：**打开权限设置** / **重启 Kaiming** / **取消**。
4. 权限页提供 **重置授权记录…**：清除 `com.kaiming.app` 的旧 TCC 记录，再重新请求授权并重启；
   这是唯一的重置入口（截图恢复框不再提供重置按钮）。
5. 从系统设置授权后切回 Kaiming：应用会在约 1 秒内自动重启一次，让 TCC 绑定到新进程，无需手动点重启。
6. 若仍异常：在系统设置中移除 Kaiming（−）后重新添加当前构建，再重启应用。

开发构建建议：固定使用同一个 app 路径与签名身份；每次更换构建路径/重新签名都可能需要重新授权。
正式分发使用稳定的 Developer ID 签名可避免此问题。

### Info.plist

`Config/Info.plist` 包含：

```xml
<key>NSScreenCaptureUsageDescription</key>
<string>Kaiming 需要屏幕录制权限来截取屏幕内容。截图仅在本机处理，不会上传到任何服务器。</string>
```

TCC 使用应用签名身份（CFBundleIdentifier + 团队 ID / 路径）记忆授权。**重新签名或换路径后
系统可能要求重新授权**，这是 macOS 行为。

## 2. 辅助功能（Accessibility）

- 只有长截图的「自动滚动」需要：通过 `CGEvent` 向选区下方窗口发送滚轮事件。
- 普通区域 / 窗口 / 全屏截图、手动滚动拼接**不需要**该权限。
- 未授权时：长截图 HUD 的自动滚动保持不可用，提示去「设置 → 权限」申请；手动滚动不受影响。
- 权限状态与申请同样只在 **设置 → 权限** 的「辅助功能」行操作。

## 3. 剪贴板

- 读取 `NSPasteboard.general` 不需要 TCC 弹窗，但 macOS 15+ 可能在后台读取时显示系统提示。
- 本实现只在 `changeCount` 变化时读取内容，并用类型检查避免无意义读取。
- 所有访问走串行队列，避免并发崩溃。

## 4. 登录项

设置 → 通用 → 「登录时自动启动」使用 `SMAppService.mainApp`：

- 已签名的 app 正常注册；
- ad-hoc / 未签名开发构建可能返回权限错误，设置页会展示系统错误文本，不会静默失败。
- 登录项不是 TCC 权限，因此不放进「权限」页，仍在通用页。

## 5. 数据与隐私

- 截图、剪贴板、Markdown 内容全部只在本机读写。
- 不包含任何网络请求代码。
- 日志使用 `os.Logger`，不含剪贴板正文/截图内容。
